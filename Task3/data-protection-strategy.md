# Задание 3 — защита данных при хранении и передаче

**As-Is:** Excel/сканы на общем диске, файловые 1С, локальный Windows Server 2022, ККМ по TCP/IP и OLE. Настройки шифрования и журналирования в кейсе не описаны. Ниже — **предлагаемые** меры: сначала для существующих файлов и 1С, затем для MVP из Task2 и будущей аналитики. Теги соответствуют [Task1](../Task1/audit-and-protection.md).

## Классы данных и обоснование

В таблице: **Х** — хранение, **П** — передача, **И** — использование; риск оценивает последствия раскрытия/изменения, а не вероятность инцидента. Для всех классов при использовании обязательны права доступа: шифрование диска не защищает открытый сотрудником файл.

| Данные / чувствительность и риск | Зачем защищать | Х: хранение | П: передача | И: использование |
| --- | --- | --- | --- | --- |
| `REG-01` — ФИО, дата рождения, контакты; высокий | Утечка идентификаторов и контактов, подмена записи. | Шифрование тома и копий, отдельные права к файлам; в MVP — отдельное хранилище. | Защищённый канал к порталу; для общего диска — защищённый SMB после проверки совместимости. | Ресепшену только нужные поля, пациенту — свои записи; аудит выгрузки. |
| `MED-01` — анкета о здоровье, карты, анализы; **очень высокий** | Раскрытие сведений о здоровье и подмена результатов. | Изолированное хранилище, шифрование файлов/копий, отдельные права и ключи. | Шифрование каждого канала обмена; будущий API лаборатории — взаимная аутентификация после согласования контракта. | Доступ по медицинской роли и пациенту/случаю, аудит чтения и экспорта; вне MVP записи. |
| `CONTRACT-01` — договоры и сканы; высокий | Личные данные и подписи, риск подмены документа. | Шифрование тома/копий, ограничение каталога, контроль целостности. | Защищённый канал при передаче файлов. | Доступ по служебной задаче, маска реквизитов в списках. |
| `PAY-01` — чеки, сумма, связь с пациентом; высокий | Финансовые сведения, риск расхождений Excel и 1С. | Шифрование файловой базы, Excel и копий; сверка записей. | Сегментация ККМ–1С; совместимость шифрования TCP/IP–OLE уточнить, до неё не считать канал защищённым. | Роли кассира/бухгалтерии, аудит изменений; без диагноза в платёжном потоке. |
| `HR-01` — кадры и зарплата; высокий | Личные и финансовые сведения сотрудников. | Шифрование файловой базы/копий, отдельные права. | Защищённый доступ бухгалтерии к 1С. | Отдельная кадровая роль, аудит, маска реквизитов вне профильных экранов. |
| `INV-01` — ТМЦ/закупки; средний, выше при наличии ПДн | Подмена остатков и документов; состав обмена двух 1С неизвестен. | Резервирование, контроль целостности и доступа; шифрование тома. | Проверить поля и механизм обмена 1С; защитить канал после проверки совместимости. | Роли склада/бухгалтерии; обнаруженные ПДн размечать отдельно. |
| Журналы, резервные копии, ключи; высокий/критический | Копии содержат те же данные; журнал и ключ могут раскрыть или обойти защиту. | Шифровать копии, ограничить доступ и срок, держать ключи отдельно, проверять восстановление. | Только защищённая доставка журналов и копий. | Разделить администрирование ключей, журналов и данных; записывать операции с ключами. |
| Будущие аналитические наборы; зависит от состава, до проверки — высокий | Возможна повторная идентификация пациента через сочетание полей. | Изолировать аналитическое хранилище, шифровать наборы и копии. | Передавать только после минимизации и проверки обезличивания, по защищённому каналу. | Доступ аналитикам к подготовленным наборам, не к исходным медкартам. |

## Реестр предлагаемых средств

| Средство | Тип / этап | Назначение и проверка |
| --- | --- | --- |
| Шифрование томов Windows Server (например, BitLocker при наличии TPM), шифрование резервных копий | ПО + аппаратный TPM / существующая среда | Файлы Excel/JPG/PDF и базы 1С при хранении; проверить совместимость, режим восстановления и защищённость ключей. |
| ACL файлового сервера, роли 1С; в MVP — политика доступа по роли и владельцу записи | ПО / существующая среда → MVP | Ограничить доступ к расшифрованным данным; проверить отказ для посторонней роли и пациента. |
| Шифрование SMB и TLS для портала; сетевые правила для ККМ и двух 1С | ПО / существующая среда → MVP | Защита каналов после инвентаризации протоколов; ККМ–OLE и обмен 1С требуют отдельной проверки. |
| Межсетевой экран/сегментация сети | Аппаратное или программное средство / существующая среда | Разделить рабочие места, ККМ, сервер и будущий портал; проверять разрешённые соединения. |
| Хранилище ключей/секретов, позднее KMS или HSM при обоснованной потребности | ПО / аппаратное HSM при выборе / MVP и развитие | Раздельный доступ к ключам, ротация, резервирование и аудит операций; конкретное средство выбирать после модели угроз. |
| Изолированное резервное хранилище/носитель | Аппаратное или программное средство / существующая среда | Защита копий от изменения и потери; регулярно проверять восстановление. |
| Сбор журналов, сканер файлов/тегов, контроль конфигураций | ПО / существующая среда → MVP | Поиск незащищённых копий, проверка ACL/шифрования, оповещение о массовом чтении и экспорте. |
| Контролируемая выгрузка с обезличиванием и проверкой результата | ПО / после MVP | Только подготовленные данные в аналитический слой; сохранять происхождение и теги набора. |

**Автоматический контроль:** периодически сверять реестр файлов и тегов с фактическими ACL, шифрованием и резервными копиями; проверять сертификаты/каналы, собирать события доступа и изменения, сигнализировать о неразмеченных копиях и массовых выгрузках. Отчёт контроля должен указывать владельца, объект и действие; отдельно проверять восстановление и ротацию ключей.

**Перед выбором средств уточнить:** фактические настройки и расположение файлов/баз, состав обмена 1С, возможности ККМ–OLE, поля и сроки хранения. Применимость специальных требований к защите ПДн и медицинских сведений, включая выбор криптосредств, определяется отдельно по правовому режиму и модели угроз.
